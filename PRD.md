# 📋 Product Requirements Document (PRD) — КиноРек

## 1. Problem Statement (Проблема)

**Боль пользователя:** Существующие сервисы (Кинопоиск, Netflix) используют "черный ящик" для рекомендаций. Пользователь не может гибко управлять критериями подбора: иногда хочется "чего-то нового и непопулярного", а иногда — "проверенной классики". Линейная лента не учитывает контекстный запрос.

**Решение:** Сервис рекомендаций с прозрачной настройкой весов алгоритма. Пользователь сам регулирует баланс между:
1.  **Популярностью** (рейтинги, просмотры).
2.  **Новизной** (год выпуска, дата добавления).
3.  **Персонализацией** (история просмотров, оценки, жанровые предпочтения).

---

## 2. Target Audience (Целевая аудитория)
- **Ядро:** Молодежь 16–25 лет, студенты, активные потребители контента.
- **Поведение:** Смотрят фильмы ежедневно, пользуются несколькими стриминговыми сервисами, ценят контроль и персонализацию.
- **Потребность:** Быстро находить фильм под конкретное настроение без долгого скроллинга.

---

## 3. Value Proposition (Ценность)
| Критерий | КиноРек | Конкуренты (Кинопоиск, Netflix) |
| :--- | :--- | :--- |
| **Управление выдачей** | Ручная настройка весов алгоритма | Только пассивный просмотр |
| **Прозрачность** | Понятные критерии (жанр, год, вес) | Скрытые алгоритмы |
| **Фокус на поведении** | Анализ оценок и истории | Чаще на основе популярности |

## 6. Non-Functional Requirements (NFR)
- **Производительность:** Время отклика API < 200 мс (p95) для эндпоинта рекомендаций.
- **Нагрузка:** Поддержка до 100 RPS (на этапе учебного проекта).
- **Безопасность:** 
  - Хэширование паролей (bcrypt/argon2).
  - Валидация всех входных данных (Pydantic).
  - JWT токены с временем жизни (access/refresh).
- **Качество кода:** Покрытие тестами > 60% (целевой показатель к концу семестра).
- **Документация:** Автогенерируемый Swagger (`/docs`).
